================================================================
PANDUAN PRAKTEK & DEMO: SOAL 8
Topik: Packet Capture 4 Tahapan DHCP (DORA) & Verifikasi giaddr
================================================================

[ TUJUAN SOAL ]
1. Merekam transaksi DHCP saat klien meminta lease baru.
2. Memperlihatkan urutan transaksi 4 tahapan:
   DHCPDISCOVER -> DHCPOFFER -> DHCPREQUEST -> DHCPACK
3. Memvalidasi nilai field giaddr sesuai interface jichi penerima request.

----------------------------------------------------------------
SKENARIO DEMO LANGKAH DEMI LANGKAH
----------------------------------------------------------------

LANGKAH 1: JALANKAN CAPTURE DI SERVER
Buka terminal node: tengen (10.68.4.10)
Ketik perintah berikut; terminal akan menunggu paket:
tcpdump -i eth0 -n -vvv 'port 67 or port 68'

LANGKAH 2: TRIGGER REQUEST DI KLIEN
Buka terminal node: itadori (jangan tutup terminal tengen).
Jalankan perintah untuk meminta lease baru:
killall udhcpc 2>/dev/null
ip addr flush dev eth0
udhcpc -i eth0 -x hostname:itadori

-x hostname:itadori mengirim hostname DHCP (Option 12), yang dicocokkan oleh class pool1.
Opsi ini kompatibel dengan versi BusyBox udhcpc pada node Alpine.

LANGKAH 3: LIHAT HASIL DI TERMINAL TENGEN
Jika transaksi berhasil, cari urutan berikut pada output tcpdump:
1. DHCPDISCOVER: request yang diteruskan relay; Gateway-IP/giaddr seharusnya 10.68.2.1.
2. DHCPOFFER: server tengen (10.68.4.10) menawarkan IP klien dari Pool 1,
   yaitu rentang 10.68.2.10 sampai 10.68.2.35.
3. DHCPREQUEST: klien meminta alamat yang ditawarkan; giaddr tetap 10.68.2.1.
4. DHCPACK: server mengonfirmasi lease untuk alamat yang ditawarkan.

Alamat klien yang ditawarkan tidak harus selalu 10.68.2.10; alamatnya dapat
berbeda selama masih berada dalam Pool 1 dan tersedia.

Perhatikan field Gateway-IP (nama tampilannya bisa berbeda menurut versi tcpdump):
giaddr = 10.68.2.1
Alamat ini adalah IP interface eth2 pada router jichi, yang terhubung ke Network 2.
Jangan gunakan kugisaki untuk demo ini karena kugisaki berada di Network 3 dan
giaddr yang diharapkan untuknya adalah 10.68.3.1.

----------------------------------------------------------------
POIN PENJELASAN UNTUK DIUCAPKAN KE ASISTEN
----------------------------------------------------------------
"Kami menjalankan tcpdump pada eth0 tengen untuk melihat empat pesan DHCP:
Discover, Offer, Request, dan Ack. Klien yang diuji adalah itadori di Network 2,
jadi field giaddr yang diharapkan adalah 10.68.2.1, yaitu IP eth2 jichi.
Server menggunakan informasi subnet tersebut untuk memberikan alamat dari
Pool 1 Network 2, yaitu rentang 10.68.2.10 sampai 10.68.2.35."
